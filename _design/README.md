# Design

Planning documents for tooling built *on top of* this repo — not campaign content. Nothing here is canon; it describes what the eventual GM and player interfaces should do.

## Read in this order

1. **[[North-Star]]** — what the whole thing is for. Decide against this when anything else is unclear.
2. **[[GM-Considerations]]** — the recurring judgment calls the tool should support but never make.
3. **[[Interface-User-Stories]]** — what each user needs to be able to do, from their perspective.
4. **[[Interface-Direction]]** — text-primary, visualization on demand; the four jobs of a visualization.
5. **[[Information-Architecture]]** — the graph model: nodes, edges, quests vs. arcs, investment.
6. **[[Arcs]]** — how arcs behave over a campaign: co-authorship, projection, merging, density.
7. **[[Canon]]** — how the party's story relates to the written one: proximity, fidelity, divergence.
8. **[[Session-Capture]]** — what gets recorded after a session, and why. The near-term deliverable.

## Constraints

Hard rules, not preferences.

- **[[Constraint-Manner-and-Intent]]** — the AI never generates manner, intent, or emotional state. Those come from the GM or from player notes.

## Open

- **[[Open-Requirements]]** — consolidated requirements questions, blocking ones marked.
- **[[Rollback-and-Repair]]** — candidate behaviors for undoing bad data. Undecided; possibly overkill.
